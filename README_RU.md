# parblo-a610-craft-driver

*In English: [README.md](README.md)*

> **Об авторстве.** Проект полностью написан Claude Opus 5. Код ревью ChatGPT 5.6 Sol.

Драйвер планшета **Parblo A610** (`UC-LOIC / TABLET 1060`, `0x5543:0x0081`,
прошивка `F401-HK708-STD`) для macOS на Apple Silicon.

Родной драйвер Parblo 2018 года заявляет только OS X 10.11–10.14. Этот —
userspace-демон на Swift: читает HID напрямую и шлёт настоящие планшетные
события CoreGraphics, с нажимом, которое понимают Photoshop, Krita,
Clip Studio и Blender.

Внешних зависимостей нет — ни libusb, ни hidapi, ни Homebrew. Только
фреймворки Apple.

Замеры, на которых всё держится, собраны отдельно: [FINDINGS_RU.md](FINDINGS_RU.md),
она же [по-английски](FINDINGS.md). Большая их часть к этой модели отношения не
имеет и пригодится любому, кто пишет драйвер планшета или борется с TCC на macOS.

> Дальнейшая разработка проекта не планируется, так как он был создан для решения конкретной
> проблемы - заставить планшет работать без поддержки на новом Mac.
> Но репозиторий будет полезен для других подобных исследований.

## Оговорки

Область применимости узкая, и лучше знать это до установки.

**Одна модель.** Драйвер написан под Parblo A610 с прошивкой `F401-HK708-STD`.
`0x5543:0x0081` используют минимум три разных планшета, поэтому опознание идёт
по строке прошивки, и чужое устройство драйвер трогать откажется. Протокольный
слой при этом общий для семейства UC-Logic v1: к конкретной модели привязаны
две константы — PID и строка прошивки. Приспособить под соседний планшет
правдоподобно и никем не проверено.

**Одна машина.** Всё измерено на одном экземпляре железа, под одной версией
macOS, у одного пользователя. Это n = 1. Заявки вида «у меня иначе» ожидаемы, и
разбирать их придётся замером — инструменты для этого лежат в
`tools/`.

**Один пользователь.** Установка персональная. При быстром переключении
пользователей планшет достанется тому сеансу, который захватил устройство
первым; подробности и способ это исправить — в разделе TODO.

**Ни наклона, ни поворота пера.** Их нет у железа.

**Экспресс-кнопки переназначению драйвером не поддаются.** Так устроена macOS;
разбор — в конце файла.

## Установка

Путей два. Первому хватает окна Терминала. Второму нужен тулчейн Swift, и он
даёт сборку из исходников, которые можно прочитать.

### Из готового архива

Для тех, кому компиляторы неинтересны. Распаковать архив, в Терминале набрать
`cd `, перетащить распакованную папку в окно, нажать Enter, затем:

```bash
./install.sh
```

Ничего не собирается: файлы внутри уже скомпилированы и подписаны. В архиве
лежит `INSTALL.txt` с теми же шагами, расписанными по нажатиям, по-русски и
по-английски.

Сборка **не нотаризована в Apple** — для этого нужен платный аккаунт
разработчика. Поэтому macOS помечает скачанные файлы карантином, а установщик
один раз спрашивает, снимать ли эту пометку, прямо говоря, что она означает.
Ответ «нет» не ставит ничего.

### Из исходников

```bash
tools/build.sh
```

Скрипт соберёт release, подпишет (на arm64 неподписанный бинарник не
запускается вовсе — требование архитектуры), поставит
LaunchAgent и запустит его. Нужен Swift, то есть Xcode или Command Line Tools.

`tools/build.sh package` собирает описанный выше архив в `dist/` и ничего не
устанавливает.

### Разрешения

Каким бы путём ни пришёл, выдать **два** разрешения. Оба — в
**Системные настройки → Конфиденциальность и безопасность**, оба на
`~/Library/Application Support/parblo-a610-craft-driver/bin/parblo-a610-craft-driver`:

| Раздел | Зачем |
|---|---|
| **Мониторинг ввода** | читать HID и захватить интерфейс планшета |
| **Универсальный доступ** | чтобы `CGEventPost` действительно отправлял события |

Второе разрешение обязательно и его легко пропустить. Без него `CGEventPost`
молча выбрасывает всё, что драйвер производит: ошибки нет, лог выглядит
успешным, а планшет при этом полностью мёртв — ведь он уже захвачен и системе
больше не принадлежит. Поэтому драйвер проверяет оба права на старте и
отказывается запускаться, пока их нет: лучше работающая грубая мышь, чем
захваченный планшет, который никуда не шлёт.

Драйвер лежит в папке, которую Finder прячет, поэтому в окне выбора файла нажми
Command+Shift+G и вставь путь. При первом запуске драйвер
ещё и сам попросит оба разрешения диалогом. Если пропустил — включи тумблеры
вручную и подтолкни агент:

```bash
launchctl kickstart -k gui/$(id -u)/com.rey.parblo-a610-craft-driver
```

### Удаление

Любой из установщиков убирает то, что ставят оба:

```bash
tools/build.sh uninstall
```

Выгружает агент, удаляет plist, закрывает и удаляет приложение настроек, убирает
бинарник. Конфиг и логи остаются — переустановка их подхватит. Чтобы снести и их:

```bash
tools/build.sh uninstall --purge
```

Планшет сразу возвращается системе и работает как обычный указатель без нажима,
то есть так же, как до установки.

Две вещи скриптом не убираются:

- **Разрешения.** В «Мониторинге ввода» и «Универсальном доступе» останутся
  строки, указывающие на удалённый файл. Убираются кнопкой минус там же. Из
  терминала чисто не выходит: `tccutil reset` работает по службе целиком и
  сбросил бы разрешения всем программам сразу.
- **Сертификат.** В цепочке `login` останется `Parblo A610 Craft Driver` и
  одноимённый приватный ключ. Другим программам он не мешает, так что удалять
  его нужно только если он больше ни для чего не нужен.


| Что | Где |
|---|---|
| Бинарник | `~/Library/Application Support/parblo-a610-craft-driver/bin/parblo-a610-craft-driver` |
| Конфиг | `~/Library/Application Support/parblo-a610-craft-driver/config.json` |
| Лог | `~/Library/Application Support/parblo-a610-craft-driver/parblo-a610-craft-driver.log` |
| Лог падений | там же, `…crash.log` — в норме пустой |
| LaunchAgent | `~/Library/LaunchAgents/com.rey.parblo-a610-craft-driver.plist` |
| Приложение настроек | `~/Applications/Parblo A610.app` |

## Запуск руками

```bash
swift build && ./.build/debug/parblo-a610-craft-driver --verbose
```

`--dump` печатает разобранный поток пера и не шлёт событий — удобно, когда
надо посмотреть, что приходит с железа, не трогая курсор. В этом режиме
«Универсальный доступ» не нужен: драйвер ничего не отправляет, поэтому и не
требует права на отправку.

Разрешения привязаны к конкретной программе: запуск из Терминала требует
тумблеров у самого **Терминала**.

> **Разрешения переживают пересборку** — но только если бинарник подписан
> сертификатом, см. раздел ниже. С ad-hoc подписью они гаснут после каждой
> правки кода.

## Лог

```bash
tail -f ~/Library/Application\ Support/parblo-a610-craft-driver/parblo-a610-craft-driver.log
```

Драйвер — фоновый процесс без интерфейса, и лог у него единственное окно наружу.
Поэтому в работе пишутся все значимые события: опознание, подключение и
отключение, переустановка режима после сна, восстановление после потери режима,
отказы по разрешениям. Около **полукилобайта в сутки** — по строке на событие,
отчёты пера не пишутся никогда.

Подробности (вход и выход пера из зоны) — только под `--verbose`, в боевом
агенте этого флага нет.

### Почему лог ведёт сам драйвер

За файл, который никто не ротирует, отвечает тот, кто в него пишет: macOS этого
не делает. Пока вывод перенаправлял `launchd`, обрезать разросшийся файл изнутри
было нечем — дескриптор открывал он.

Теперь драйвер открывает файл сам, следит за размером и при достижении мегабайта
переименовывает текущий в `.1` и начинает новый. Одна старая копия сохраняется,
предел не превышается: проверка идёт **до** записи, иначе свежая строка уезжала
бы в старый файл вместе с ротацией.

Переименование может не пройти — каталог только для чтения, `.1` кем-то занят.
Тогда файл режется на месте через собственный дескриптор: прав на каталог для
этого не нужно. Ротация при этом не переспрашивает размер у себя же — прежняя
схема на неудачном переименовании уходила в бесконечную рекурсию и роняла демон,
а `KeepAlive` превращал падение в цикл перезапусков.

`launchd` остаётся вывод на случай падения — отдельный `…crash.log`, который в
нормальной работе не растёт вовсе.

Запущенный руками драйвер пишет в терминал: решение принимается по `isatty`, и
`--dump` работает благодаря этому.

Всё это — обычная Foundation: `FileManager` и `FileHandle`, плюс `isatty`.
Внешних зависимостей нет.

## Приложение настроек

`~/Applications/Parblo A610.app` — значок в строке меню и окно калибровки.
Ставится тем же установщиком.

**Разрешений не требует ни одного.** Ни «Мониторинга ввода», ни «Универсального
доступа» — это следствие устройства: связи с драйвером у приложения нет.

| Что | Как |
|---|---|
| Настройки | пишет `config.json`; драйвер следит за файлом и перечитывает на лету |
| Живой нажим и координаты пера | получает планшетными событиями, как любой редактор |

Ни сокетов, ни XPC, ни общей памяти. Оба механизма существовали и до
приложения.

Отсюда же следует, чего приложение знать не может. Плашка вверху говорит про
агент launchd: жив процесс или нет. Про планшет — подключён ли он и отвечает ли
перо — говорит строка ниже, по давности последнего события пера. Конфиг
приложение читает через тот же `ConfigStore`, что и драйвер, поэтому правка
файла снаружи при открытом окне подхватывается; прежде её затирало следующее
движение ползунка.

### Что в окне

- **Экран** — куда выводить, поворот, подгонка пропорций.
- **Рабочая область** — прямоугольник таскается и тянется за уголок. Пунктиром
  показано, что реально попадёт на экран после подгонки пропорций; оранжевая
  точка — перо в реальном времени, сразу видно, куда дотягивается рука.
  Считает это тот же `ScreenMapper`, что и драйвер: предпросмотр не должен
  рисовать свою версию расчёта.
- **Кнопки пера** — назначение боковых клавиш.
- **Нажим** — кривая с линейной для сравнения, ползунки гаммы и отсечек, живая
  точка на кривой и место, где можно провести линию пером и увидеть толщину.
  Вслепую кривую не подобрать, ради этого редактор и нужен.

Приложение видит уже пересчитанный драйвером нажим, поэтому точка на кривой
ставится обратным преобразованием — иначе она стояла бы не на той оси.

### Сборка бандла

SwiftPM собирает голый исполняемый файл: без `Info.plist` у процесса нет
идентификатора бандла и система не считает его приложением. Обёртку делает
`build.sh` и подписывает тем же сертификатом, что и драйвер. Проекта Xcode в
репозитории нет — всё собирается одним `swift build`.

## Конфиг

Файл создаётся сам при первом запуске и перечитывается на лету — перезапуск не
нужен. Отсутствующие ключи берутся по умолчанию, так что можно оставить только
то, что меняешь.

```json
{
  "display": "main",
  "activeArea": { "x": 0.0, "y": 0.0, "width": 1.0, "height": 1.0 },
  "lockAspectRatio": true,
  "orientation": 0,
  "pressure": { "min": 0.02, "max": 0.95, "gamma": 0.75 },
  "penButtons": { "barrel1": "rightClick", "barrel2": "middleClick" }
}
```

| Ключ | Смысл |
|---|---|
| `display` | `"main"` либо номер экрана в списке активных, считая с нуля: `"1"` |
| `activeArea` | рабочая часть планшета в долях от всей области, поэтому не зависит от разрешения |
| `lockAspectRatio` | подогнать область под пропорцию экрана, чтобы круг оставался кругом |
| `orientation` | `0`, `90`, `180`, `270` |
| `pressure.min` / `.max` | мёртвая зона внизу и насыщение вверху, в долях сырого диапазона |
| `pressure.gamma` | `< 1` мягче (лёгкое касание даёт больше), `> 1` жёстче, `1` линейно |
| `penButtons.*` | `none`, `leftClick`, `rightClick`, `middleClick` |

Про `lockAspectRatio`: планшет 5:3 (1,667), экран мака ~1,54. Без подгонки
горизонталь растягивается сильнее вертикали, и круг выходит эллипсом.

Про `gamma`: обычное рабочее нажатие на этом железе даёт ~1450–1520 из 2047 —
то есть 0,71–0,74 шкалы. Верхняя четверть почти недостижима, вся тонкая работа
сжата в нижнюю половину. Если тонкая линия даётся тяжело — уменьшай гамму;
если полный диапазон достигается слишком рано — увеличивай.

Боковая клавиша пера перебивает кончик: удерживая её, рисуешь назначенной
кнопкой. Кнопка не меняется посреди штриха — нажатая по ходу клавиша не
превратит левый штрих в правый.

## Как это устроено

```
USB control transfer, строка #100  →  полный режим планшета
IOHIDManager, ИФ0 (0x0D/0x02), seize  →  Report ID 7, 8 байт, ~130 Гц
ReportParser  →  PenState
ScreenMapper + PressureCurve  →  координаты экрана и нажим 0…1
CGEvent (subtype TabletPoint / TabletProximity)  →  приложения
```

Четыре вещи, на которых всё держится:

1. **Инициализация обязательна.** Планшет включается в режиме совместимости и
   шлёт перо на интерфейс 1 с разрешением 2048×2048; интерфейс 0 при этом
   молчит. Чтение строкового дескриптора №100 переводит его в полный режим
   40000×24000 (`hid-uclogic-params.c`: *«NOTE: This enables fully-functional
   tablet mode»*). Это **чтение**, в устройство ничего не пишется. Режим
   держится после закрытия USB-хэндла, поэтому делается один раз на подключение
   и повторяется после пробуждения из сна.

2. **Захват обязателен.** `DeviceOpenedByEventSystem = Yes` — системная служба
   событий сама обрабатывает планшет и двигает курсор. Без
   `kIOHIDOptionsTypeSeizeDevice` курсор получал бы две команды сразу.
   Проверено замером: под seize отчёты приходят драйверу, а планшетных событий
   от системы — ноль.

3. **Proximity обязателен, и формы его две.** Без событий входа и выхода из
   зоны приложение не признаёт устройство планшетом и молча игнорирует нажим.
   Мышиного события с подтипом `2` при этом **недостаточно**: приложения на Qt
   (Krita, Clip Studio) регистрируют планшет только по настоящему событию типа
   `kCGEventTabletProximity`, которое доходит до них как
   `NSEventTypeTabletProximity` и вызывает `tabletProximity:`. Мышиный вариант
   приходит как `mouseMoved`, и обработчик планшета его отвергает — Qt не
   находит устройство по `deviceID` в точечных событиях и обрабатывает поток
   как обычную мышь. Симптом узнаваемый: курсор идёт плавно, круг круглый,
   боковая кнопка щёлкает — а нажим не работает, и нигде ни одной ошибки.
   Драйвер шлёт оба варианта.

4. **Прав нужно два, и второе тихое.** «Мониторинг ввода» открывает чтение и
   захват, «Универсальный доступ» — отправку. `CGEventPost` при отсутствии
   второго ничего не возвращает и никуда не жалуется, события просто исчезают.
   Проверено замером: при `IOHIDCheckAccess(kIOHIDRequestTypePostEvent) = denied`
   посланное событие не двигает курсор.

Интерфейс 1 (Mouse) — ловушка: он тоже отдаёт перо с нажимом, но координаты в
20 раз грубее. Драйвер слушает его **без захвата** и ровно для одного: в полном
режиме этот интерфейс молчит, поэтому любой его отчёт означает, что планшет
потерял полный режим — и надо перечитать строку №100. Иначе такая потеря
осталась бы незамеченной навсегда: переинициализация привязана к событию
подключения, а кабель при этом никто не трогал.

Интерфейс 2 (Keyboard) — экспресс-кнопки, они шлют фиксированные сочетания из
прошивки и работают без драйвера; драйвер его не открывает.

### Байт флагов Report ID 7

Дескриптор ИФ0 объявляет `Usage(In Range)` на бите 6, а бит 7 — набивкой
(`Input (Constant)`). Прошивка своему же дескриптору не соответствует — обычное
дело для UC-Logic, ровно поэтому Linux этим планшетам дескриптор целиком
подменяет. Замер 31.08.2026, 6535 отчётов:

| Бит | Что объявлено | Что шлёт устройство |
|---|---|---|
| 0 | касание кончиком | так и есть |
| 1 | нижняя кнопка пера | так и есть |
| 2 | ластик | **верхняя кнопка пера** |
| 3 | перо перевёрнуто | не встречается |
| 4 | вторичное касание | не встречается |
| 5 | верхняя кнопка пера | не встречается |
| 6 | перо в зоне | **перо вышло из зоны** |
| 7 | набивка | стоит в каждом отчёте, смысла не несёт |

Перо считается в зоне, пока бит 7 стоит, а бит 6 сброшен. Все восемь отводов
пера в замере закончились байтом `C0` — это последний отчёт перед тишиной.

Отрабатывается бит 6 не сразу. Пока перо висит на границе высоты
чувствительности, он моргает: в замере 29 таких морганий уложились в 118 мс, а
все настоящие отрывы пера длились от 226 мс. Поэтому отчёт с битом 6 запускает
отсчёт в 150 мс, а любой отчёт «в зоне» его отменяет. Сам отчёт в трекер кнопок
не попадает: он приходит с нулевым нажимом и сброшенными битами и отпускал бы
кнопку, которую рука держит. Без этого в Krita залипал режим перемещения холста.

Таймаут молчания в 250 мс остаётся страховкой на случай, когда поток просто
прекращается: выдернули кабель, планшет потерял полный режим.

Ластика у этого пера нет. Бит 2 — верхняя кнопка, и трактовка его как ластика
означала, что средний клик не работал вовсе, а вход в зону с зажатой верхней
кнопкой приложение видело как ластик.

## Чего нет

- **Наклона и поворота.** Их нет у железа: `kCGTabletEventTiltX/Y` и
  `Rotation` в событиях не выставляются, в `CapabilityMask` соответствующие
  биты не подняты.
- **Переназначения экспресс-кнопок.** macOS отказывает в захвате клавиатурного
  интерфейса с кодом `kIOReturnNotPrivileged` — защита от клавиатурных шпионов,
  и вопрос этим закрыт навсегда. Читать отчёты оттуда можно, отобрать у системы
  — нет. Подробности ниже.
- **Локализации интерфейса.** Окно настроек на английском, кода для смены
  языка нет.

```bash
swift test
```

Десять наборов. Покрыты чистые функции — те, где ошибка не видна глазом:

| Набор | Что проверяет |
|---|---|
| Приложение настроек | разбор состояния драйвера, значение экрана для конфига, чтение и запись файла, перехват внешней правки конфига |
| Разбор отчёта | сборка чисел младшим байтом вперёд, отбрасывание номера отчёта, флаги по тому, что шлёт устройство, обе качельки на тех битах, которые устройство действительно использует, короткий и длинный буфер |

| Зона пера | порог между замеренными морганиями и настоящими отрывами, отмена отсчёта возвратом пера, выход по тишине |
| Счётчик кликов | счёт по кнопке и по месту, системный интервал, предел в три |
| Маппинг координат | центр в центр, одинаковый масштаб по осям, все четыре поворота, рабочая область, вертикальный экран, экран со смещением |
| Кривая нажима | края, монотонность, гамма, вырожденные настройки |
| Разбор и запись конфига | умолчания, частичный конфиг, мусор в значениях, совпадение файла по умолчанию с кодом |
| Ротация лога | переполнение с сохранением прошлой копии, каталог только для чтения |

Тест, который проходит и на сломанном коде, бесполезен, поэтому набор про

Маппер принимает границы экрана параметром — иначе тесты зависели бы от

## Подпись

На arm64 неподписанный бинарник не запускается вовсе — это требование
архитектуры; Gatekeeper здесь ни при чём. Чем именно подписано, решает судьбу
выданных разрешений.

У **ad-hoc** подписи (`codesign -s -`) в требование входит отпечаток
содержимого:

```
designated => cdhash H"2814fd9e…"
```

Изменился байт — изменился отпечаток, и для macOS это другая программа:
строки в списках разрешений остаются, а тумблеры гаснут. При активной работе
над кодом это происходит после каждой сборки.

С **сертификатом** требование ссылается на сертификат и идентификатор, а
содержимое в него не входит:

```
designated => identifier "com.rey.parblo-a610-craft-driver"
              and certificate leaf = H"c32d7356…"
```

Проверено: два бинарника с заведомо разным содержимым, подписанные одним
сертификатом, дают побайтово одинаковое требование; после правки исходника и
переустановки драйвер запускается, не спрашивая разрешений заново.

### Как завести сертификат

Годится самоподписанный, Apple Developer ID не нужен. Пароль администратора
тоже не нужен — всё происходит в личной связке ключей.

Речь именно о сертификате, который ты создаёшь у себя на машине и доверяешь
только для подписи кода. Никакого стороннего корневого сертификата в систему не
добавляется, доверие не распространяется на SSL, и за пределы твоего компьютера
он не выходит.

```bash
open "/System/Library/CoreServices/Applications/Keychain Access.app"
```

1. **Keychain Access → Certificate Assistant → Create a Certificate…**
2. Имя `Parblo A610 Craft Driver`, тип объекта **Self Signed Root**, тип
   сертификата **Code Signing**. Отметить «Let me override defaults» и задать
   срок 3650 дней, иначе через год всё повторится.
3. Найти созданный сертификат в связке `login`, открыть двойным кликом,
   раскрыть **Trust** и поставить **Code Signing → Always Trust**. Закрыть
   окно, ввести пароль учётной записи.
   Только строку Code Signing: верхняя строка выставила бы доверие по всем
   назначениям, включая SSL, а это шире, чем нужно.
4. При первой сборке система спросит доступ к закрытому ключу. Ответить
   **Always Allow** («Всегда разрешать»), а **не** Allow («Разрешить»).

   Allow обычно стоит в фокусе и нажимается по инерции, а действует он на
   текущий запуск, после чего диалог возвращается при каждой сборке. Always Allow вносит `codesign` в
   список доверенных программ для этого ключа, и вопрос исчезает навсегда.

   Если уже нажал Allow: открой связку `login`, категорию **Keys** («Ключи»),
   найди ключ `Parblo A610 Craft Driver`, двойной клик → вкладка **Access
   Control** → добавь `/usr/bin/codesign` в список разрешённых программ.
   Либо просто дождись следующего диалога и нажми правильную кнопку.

Проверка:

```bash
security find-identity -v -p codesigning
```

Должно найтись одно пригодное удостоверение. Если сертификата нет,
`build.sh` подпишет ad-hoc и предупредит об этом.

Имя сертификата задаётся в `tools/common.sh` переменной `IDENTITY`.

Раздавать драйвер другим людям самоподписанный сертификат не позволит — для
этого нужен Developer ID и нотаризация ($99 в год). Для своей машины это не
требуется.

### Мелочь, о которой легко забыть

Подпись сертификатом **недетерминирована**: в неё попадает время подписания,
и два прогона над одним и тем же кодом дают разные файлы. Поэтому `build.sh`
сравнивает не файлы целиком, а `CDHash` — хеш собственно кода, времени в нём
нет. Иначе проверка «не трогать неизменившийся бинарник» молча перестала бы
срабатывать.

### Многопользовательский режим

Сейчас установка **персональная**: драйвер работает только у того пользователя,
который его поставил. Другому пользователю той же машины он не достанется, и
причин сразу четыре:

| Что | Где лежит | Почему не видно другому |
|---|---|---|
| plist агента | `~/Library/LaunchAgents/` | у него в домене задания просто нет |
| бинарник | `~/Library/Application Support/parblo-a610-craft-driver/bin/` | `~/Library` имеет права `drwx------` |
| конфиг | там же | то же самое |
| разрешения TCC | `~/Library/Application Support/com.apple.TCC/TCC.db` | **у каждого пользователя своя база** |

Обходной путь есть уже сейчас: второй пользователь запускает установщик
у себя. Скрипт весь построен на `$HOME`, так что поставит всё в его дом, с его
конфигом и логом; исходники читаются, если каталог проекта открыт на чтение.
Останется включить два тумблера.

Но при **быстром переключении пользователей** это всё равно упрётся в захват.
Сеанс предыдущего пользователя не завершается, его LaunchAgents продолжают
работать, а `kIOHIDOptionsTypeSeizeDevice` эксклюзивен — второй драйвер
устройство не получит. Ведёт себя это честно, `DeviceWatcher` пишет в лог
«Устройство занято другим процессом», но работать не будет, пока первый
пользователь не выйдет из системы.

Чтобы сделать по-настоящему, нужны три вещи:

1. Бинарник — в общедоступное место: `/usr/local/bin` или
   `/Library/Application Support/…` на месте домашнего каталога.
2. plist — в `/Library/LaunchAgents`: оттуда агенты загружаются в **каждый**
   графический сеанс. Требует прав администратора.
3. Драйвер должен **отдавать устройство**, когда его сеанс становится
   неактивным, и забирать обратно, когда снова активен —
   `NSWorkspace.sessionDidResignActiveNotification` и
   `sessionDidBecomeActiveNotification`. Без этого пункты 1 и 2 приведут лишь к
   тому, что за захват будут драться несколько процессов, и выиграет успевший
   первым.

Третий пункт — основная работа, и без него первые два бессмысленны. Разрешения
TCC останутся персональными в любом случае: это устройство самой macOS, обойти
его нечем.

## Экспресс-кнопки

Восемь кнопок на планшете шлют фиксированные сочетания из прошивки. Драйвер их
не трогает: клавиатурный интерфейс он не открывает.

Что шлёт каждая, сверху вниз — снято `tools/keyscan.c` 25.08.2026:

| # | Отчёт | Сочетание | Замысел |
|---|---|---|---|
| 1 | `03 04 3D` | Alt + F4 | закрыть окно *(Windows)* |
| 2 | `03 01 16` | Ctrl + S | сохранить *(Windows)* |
| 3 | `03 02 56` | Shift + цифр. − | уменьшить масштаб |
| 4 | `03 02 57` | Shift + цифр. + | увеличить масштаб |
| 5 | `03 01 1A` | Ctrl + W | закрыть *(Windows)* |
| 6 | `03 01 19` | Ctrl + V | вставить *(Windows)* |
| 7 | `03 01 1B` | Ctrl + X | вырезать *(Windows)* |
| 8 | `03 01 06` | Ctrl + C | копировать *(Windows)* |

Прошивка рассчитана на Windows, где основной модификатор — Ctrl. На macOS это
Cmd, поэтому шесть из восьми по умолчанию не делают ничего. Кнопки 3 и 4 при
этом печатают `-` и `+`, а в Krita это как раз масштаб.

### Как ими всё-таки пользоваться

**Привязать в редакторе.** Все восемь шлют различимые сочетания, и в Krita,
Photoshop, Clip Studio они назначаются на любое действие. На macOS сочетания с
Ctrl почти всегда свободны — Cmd занимает их место, — так что конфликтов нет.
Это работает сегодня и не требует ни строчки кода.

**Переназначить на уровне системы.** Захватить интерфейс и подменять события
нельзя: macOS отвечает `kIOReturnNotPrivileged`. Из готового подходит
[Karabiner-Elements](https://karabiner-elements.pqrs.org/) — он умеет правила,
привязанные к конкретному устройству через
[`device_if`](https://karabiner-elements.pqrs.org/docs/json/complex-modifications-manipulator-definition/conditions/device/)
с `vendor_id` и `product_id`. Для этого планшета это `21827` и `129`
(десятичные `0x5543` и `0x0081`), так что правила затронут только кнопки
планшета и не тронут настоящую клавиатуру.
